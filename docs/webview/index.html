Archify 生成体验重构计划中
把"等 4 分钟黑盒"变成"几十秒有产出、全程看得见"。速度、透明、随时能停是一体的。
痛点
  • 生成要等非常久 —— 实测 3 张图约 4 分钟，耗时全在模型侧（渲染仅 93ms）。
  • 过程不可见 —— 只有一个转圈 + 2.5 秒轮询产物，不知道在读什么、第几张图、第几轮修复。
  • 无法聚焦 —— 系统很大，只想看某一个点/某一部分，没有指定范围的交互。
  • 出图与意图不符 —— 要的那张图没出来，出来的是另一种，且"完全不对"。
已定方向
  • 确定性预扫描产出"仓库事实清单 + ≤40KB 精简摘要"直接喂模型，砍掉探索轮次（模型想三四次即可出结果）。
  • 流水线由 daemon 接管，阶段真实上报：扫描 / 出图 / 校验 / 交付。
  • 多张图并行，以"父任务 + 子 agent"层级呈现，侧边栏不散落；worker 交付后自动归档。
  • 渐进交付：每张都是成品、按序先出，架构图先可见，其余后台继续。
  • 可取消（停掉未完成项、保留已交付）；失败隔离；一个"重跑未完成"入口。
  • 证据包新鲜度：仓库版本或工作区有变化才重扫，否则复用。
  • 先扫出候选锚点（模块/入口/链路）让你确认，再动笔出图。
  • 进度展示：阶段 + 每张图状态与用时 + 实时动作行 + 失败原因。
明确排除 v1
  • 骨架直出 IR、草稿先出后替换、单张独立按钮、换模型重跑。
  • 渲染链路优化（93ms，没有优化价值）、改动产物存储格式。
笔记增强计划中
现在的笔记是"内容摘要器"，要的是"书签 + 待办收件箱"。
痛点
  • 记的是文本内容，不是位置。
  • 记完回不去 —— source 存了 workspaceId/agentId，界面却从不渲染、点不了，跳转能力为 0。
  • 没有"待处理" —— organizedAt 是"已并入正文"，不是"已处理"，笔记只会堆积，不能当清单清空。
  • 重心错位在 AI 合成正文，带来失败态、重试、状态行这些复杂度。
已定方向
  • 一条笔记 = 锚点（会话 / 消息 / 文件+行 / 那张图 / PR）+ 一句自述；文本降级为附件。
  • 条目主操作是"回去"，走 navigateToAgent 落到会话，有 messageId 则落到该条消息。
  • 新增"待处理"状态，收件箱默认只看未处理，处理完勾掉。
  • 会话内一个按钮 → 弹窗预填当前位置，补一句话即存。
  • AI 正文降级为可选的后台附加，不挡在"记"和"跳"中间。
  • 目标闭环：开发 → 反馈的工作台（随手记问题点 → 收工逐条跳回确认 → 汇成反馈）。
  • 先做"可跳转 + 待处理"这一件。
