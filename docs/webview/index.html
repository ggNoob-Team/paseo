痛点想法 1 项 · 真实使用中的摩擦与灵感，先记录，后整理成需求

会话切换 / 回前台都要重连、等很久会话痛点
两个高频场景都很慢：切换一个会话要重新连服务器、更新数据；手机从后台回前台也必定重连，过程中看不到在做什么。
现状
切换会话 → 触发连接 / 刷新 → 等很久才看到内容。回前台同样：3 秒存活探测（ packages/client/src/daemon-client.ts:1593）、重连退避 1.5s→30s（ packages/client/src/daemon-client.ts:6677）、建连超时 15s；连上后重新拉服务器信息 / 会话列表 / 时间线。
期望
缓存优先：先用已有缓存 / 已加载数据出内容，再后台增量更新；重连与刷新有可见进度；避免每次全量重拉。
备注
Paseo 已有 replica-cache / directory-sync 的缓存优先设计，需要定位实际阻塞在会话切换、timeline 全量拉取还是服务器信息重拉。未整理成需求，先记录。

角色与身份模型（人 + 角色标签）协作计划中
身份是“人”，角色只是挂在人身上的标签。例如：书记是一个人；产品、开发是他的角色标签。同一个人可以同时是产品 + 开发，角色可以变，身份不变。
需求
  • 建立“人”作为唯一身份；角色（产品 / 开发 / 测试 / 设计等）作为可多选的标签。
  • 任务分配、权限、进度归属、AI 转述都以“人”为主体，角色只用于说明职责。
  • 不要把角色当成人，也不要为每个角色建一个账号。
关联

  • 设置项：默认打开方式 = App WebView / 系统浏览器。
  • 系统浏览器：调用系统默认浏览器，复用现有 openExternalUrl 路径。
  • App WebView：复用工作区 Tab 系统（顶部多 Tab），和打开本地 HTML 文件的行为一致。
开放问题
  • WebView Tab 是否允许继续导航？当前本地 HTML preview 是 viewer，会拦截后续导航。
  • 设置粒度是全局，还是按来源（笔记 / 聊天 / PR）分别配置。
  • Tab 的 URL 是否要持久化，重开工作区是否恢复。
相关
本地 HTML 文件当前已经会新增 file Tab（openWorkspaceFileFromExplorer / WorkspaceFileTabTarget）；Bug「笔记里的链接没用外部浏览器打开」是这个能力的一部分。
